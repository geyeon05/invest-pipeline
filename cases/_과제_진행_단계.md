# 기자본 과제 진행 단계

사용자 결정 2026-11-20. 단계마다 사용자가 하나씩 정했다. 바꿀 때는 사용자와 정한 뒤 이 문서를 고친다.

## 시작

- 사용자가 **"기자본 과제 시작 N주차"**라고 하면 이 문서를 따른다.
- 과제 폴더: `cases/N주차_사례이름/`
  - `대응표.md`: 2단계에서 승인한 대응표 (양식: `cases/_대응표_양식.md`)
  - `진행.md`: 지금 몇 단계인지, 정한 것, 역할 기록
  - 단계별 결과 파일
- 새 창에서 다시 시작하면 **`진행.md`를 먼저 읽고** 이어서 한다.
- 판단 기록은 투자 분석과 **같은 공책 양식**을 쓴다 (`analyses/_투자_분석_단계.md` '공책 양식'). 과제 폴더 안에:
  - `case.json` 과제 정보·대응표·분석할 회사·지금 단계 / `_book/` 과제 공책(질문 q1… · 주장 claim) / `companies/` 과제용 회사 공책(3단계, 실제 투자 공책과 따로) / `진행.md` 저절로 만들어지는 요약
  - 화면: 과제 방 탭 (http://localhost:8501, 주소에 `?case=과제ID`). 질문·주장·회사 단계의 초안·확정·확인함은 화면에서, 피드백은 대화창에서.
- **명령 (Claude가 대화창에서 사용자와 정한 것을 적을 때):**
  - 1단계: `uv run data.py case 5주차_사례2 --new --title "…" --week 5 --in-file "…" --pre-file "…"`
  - 2단계: 대응표 JSON(summary, alternatives, deliver, pre_concepts[{name, desc}], questions[{q, pre, need, parts, missing}])을 써서 `case 과제ID --table-file 파일 --stage 2` → **사용자가 승인하면** `--approve`
  - 3단계: `case 과제ID --companies "회사1,회사2" --run --stage 3` (내 9단계 계산, 외부 요청 없음)
  - 단계 넘어가기: `case 과제ID --stage N` · 보기: `case 과제ID` · 목록: `case list`
  - 6단계: 보고서 md를 `reports/과제ID_보고서.md`로 쓴 뒤 `case 과제ID --report-file reports/과제ID_보고서.md --outputs` (또는 화면 6단계의 '검증표·역할구분 만들기'). 검증표의 '직접 쓴 숫자'는 Claude가 원문과 대조해 결과를 사용자에게 보고한다
  - 피드백: 회사 단계 `note 회사 --case 과제ID --step N --item M --feedback "…"` / 질문·주장 `note 과제ID --case-book --step q2 --item 1 --feedback "…"` (확인할 것은 `--add-check`, `--done-check`)

## 모든 단계 공통

- 바꾸는 작업(파일 생성·수정, 자료 받기, 커밋·푸시)은 **승인 후**에 한다. 자료를 받을 때는 요청 수를 먼저 알린다.
- 설명은 쉬운 말로 하고, 사용자가 **이해했다고 말한 뒤** 다음으로 넘어간다.
- 판단은 **초안 → 피드백 → 확인할 것 → 확정**을 거친다.
  - 피드백은 정답이 아니라 반대되는 사실, 빠진 자료, 내 성향(`investor_profile.md`)과 어긋나는 점을 짚는다.
  - 피드백에서 나온 '확인할 것'은 기존 부품 / 자료 받기(승인) / 새 도구(옮겨 적기·임시·정식 중 의논)로 처리한다.
  - **확인할 것이 하나라도 남으면 확정하지 않는다.**
- `진행.md`에 단계마다 **'사용자가 정한 것·판단한 것'**과 **'AI가 한 것'**을 나눠 기록한다. 6단계 역할 구분 PDF의 재료가 된다.
- 모든 수치에는 출처를 단다 (`CLAUDE.md` 2장).

## 1단계: 과제 자료 읽고 이해하기

1. 기본 위치 `C:\Users\dokyu\OneDrive\바탕 화면\기자본 자료`에서 `N주차_IN*`와 `N주차_PRE*` 파일을 **함께** 읽는다. 파일 이름 뒤의 "(1)" 같은 번호는 무시한다.
   - 파일이 없으면 알리고 기다린다. 추측해서 다른 파일을 읽지 않는다.
2. 사례가 여러 개면 목록을 보여주고 사용자가 고른다.
3. 그 사례가 묻는 것(과제의 질문, 대안, 제출할 것)과 **이번 주 PRE 관점**을 쉬운 말로 설명한다.

끝: 사용자가 이해했다고 하면.

## 2단계: 대응표 만들기

1. 과제의 질문을 원문에 가까운 말로 뽑는다.
2. 질문마다 **PRE 관점**을 연결한다.
3. 질문마다 필요한 재료와 쓸 부품을 짝짓는다. 3단계의 9단계 결과로 답할 수 있으면 **"9단계 ○번 사용"**이라고 적는다.
4. 9단계로도 안 되는 것은 **'없으면' 칸**에 적는다 (4단계에서 의논).
5. **분석할 회사 목록**과 **받아야 할 자료·요청 수**를 적는다.
6. 쉬운 말로 설명한다 → 사용자가 고치거나 **승인**한다 → `대응표.md`에 저장한다.

끝: 사용자가 대응표를 승인하면.

## 3단계: 과제에 나온 회사를 내 9단계로 분석

과제 보고서의 시야가 좁아지지 않도록, 과제 질문에 답하기 전에 먼저 내 기준으로 회사를 본다.

9단계 (2026-11-20 확정, 바뀔 수 있음): 1 약속 이행 · 2 현금 창출 · 3 자본 배분 · 4 이익의 질 · 5 재무 안전성 · 6 특수관계자 · 7 정성 자료 · 8 가격 판단 · 9 최종 판단

1. 회사 목록을 확인하고 자료를 받는다 (요청 수를 알리고 승인).
2. 1~8번을 **단계별로** 진행한다. 단계마다 모든 회사를 한 표에 놓고 비교한다.
   - 기준을 충족한 것은 '단순 정보', 경고가 있거나 판단이 필요한 것은 '논의할 부분'으로 나눈다.
   - 논의할 부분은 초안 → 피드백(회사끼리 **비교하는 눈으로**) → 확인할 것 → 확정.
3. 1번 약속 이행에서 **탈락한 회사도 끝까지 본다**. 표에 탈락 표시만 붙인다.
4. 결과는 **단계별 보기와 회사별 보기**로 둘 다 볼 수 있게 저장한다.
5. 9번 최종 판단은 하지 않는다. 5단계의 주장으로 대신한다.

엔진이 아직 없으면 있는 부품으로 단계마다 손으로 진행한다. 아직 돈을 못 버는 회사처럼 단계가 맞지 않는 경우는 그대로 보고하고 표시 방법을 사용자와 정한다.

끝: 1~8번의 논의할 부분을 모두 확정하면.

## 4단계: 과제 질문에 답하기

1. 대응표의 '없으면' 칸의 방법을 정한다: 공시 본문에서 옮겨 적고 원문과 대조 / 과제용으로 만들기 / 정식 부품으로 만들기 (사용자 승인).
   - 새 부품은 `criteria/README.md` 2장에 올리고, 과제용이면 **'과제용'** 표시를 한다.
2. 추가로 받을 자료가 있으면 요청 수를 알리고 승인받는다.
3. 질문마다 결과를 정리한다. 3단계 결과를 가져다 쓰고 출처를 붙인다.
4. 질문마다 초안 → 피드백 → 확인할 것 → 확정.

끝: 대응표의 질문을 모두 확정하면.

## 5단계: 주장 정하기

1. 확정한 답과 3단계 결과를 모아 **대안별로 유리한 점과 불리한 점**을 정리한다.
2. 사용자가 대안을 고르고 이유를 쓴다 (초안).
3. 냉정한 피드백을 주고, **반박해야 할 주장**을 정리한다.
4. 대안을 고른 **뒤에** PRE 관점으로 근거를 정리한다.
5. 확인할 것 → 고친 주장 → **확정**.
6. **출처·수치 검증표**: 확정한 결론에 쓰인 수치만 공시 원문과 대조한다 (일치 / 계산값 / 불일치).
   불일치가 있으면 수치를 고친 뒤 결론이 바뀌는지 다시 확인한다.

끝: 주장을 확정하고 검증표에 불일치가 없으면.

## 6단계: 보고서

1. 사용자가 보고서 뼈대를 준다 (매번).
2. Claude가 뼈대에 맞춰 **확정한 판단·근거·검증한 수치로만** 초안을 쓴다. 새 주장을 넣지 않는다.
3. 사용자가 고칠 곳을 말하면 고친다 (반복).
4. 사용자가 "내도 된다"고 하면 `reports/`에 아래 세 가지를 md와 PDF로 만든다.
   - `N주차_사례이름_보고서`: 최종 보고서
   - `N주차_사례이름_검증표`: 결론에 쓴 수치마다 출처(공시·접수번호·절), 원문 대조 결과(일치/계산값/불일치), 계산값이면 계산식
   - `N주차_사례이름_역할구분`: `진행.md` 기록으로 만든 표. 단계마다 사용자가 정한 것·판단한 것과 AI가 한 것(자료 수집, 계산, 초안, 피드백). **기록에 있는 것만** 적는다
5. 커밋·푸시는 사용자가 지시할 때만 한다. md만 올리고 PDF는 올리지 않는다. 매번 `.env`가 들어가지 않았는지 확인한다.

끝: 세 문서를 만들면.

## 7단계: 마무리

1. 이번 과제에서 만든 과제용 부품 목록을 보여주고, 정식 부품으로 올릴지 사용자가 정한다.
2. AI가 정한 세부 값이 `criteria/README.md`의 "AI가 정한 값" 표에 기록됐는지 확인한다.
3. 과제를 '완료'로 표시하고 `진행.md`를 정리한다.
4. 이번 주 PRE 관점 중 **내 9단계 기준에 넣을지 고민할 갈림길**이 있으면 제시한다. 성향에 따라 어떻게 갈리는지만 보여주고 추천하지 않는다. 넣을지는 사용자가 정한다.

끝: 1~4를 모두 마치면 과제 완료.
